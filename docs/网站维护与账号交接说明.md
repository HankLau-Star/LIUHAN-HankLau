## 2. 稳健架构

```text
GitHub main（唯一源码）
  ├─ Cloudflare Workers Builds ──> 全栈主站
  │                              ├─ D1：文字、数值、作品资料
  │                              ├─ R2（可选）：后台上传的图片、视频、音频、PDF
  │                              └─ GitHub OAuth：所有者账号登录后台
```

## 7. 账号与密钥规则

- GitHub 密码、Cloudflare 密码、验证码、访问令牌、Cookie、私钥不得写入代码、文档、Git remote 或聊天。
- Cloudflare 运行时变量只在控制台保存：`AUTH_PROVIDER`、`ADMIN_EMAILS`、`ADMIN_GITHUB_LOGINS`、`GITHUB_OAUTH_CLIENT_ID`；客户端密钥与会话密钥必须保存为 Cloudflare Secret。
- `ADMIN_EMAILS` 与 `ADMIN_GITHUB_LOGINS` 是允许列表，不是密码；OAuth App 只申请 `read:user`。
- `/api/admin/*` 在服务端重新验证签名会话和允许账号；不能只保护后台页面而放开写入 API。
- 删除 D1、R2、Worker、仓库、Pages 或旧站都属于破坏性操作，必须先备份并得到所有者明确确认。

## 8. 故障恢复

- Cloudflare 主站异常：先打开 GitHub Pages 镜像；页面还能使用代码中的默认内容。
- Cloudflare 构建失败：查看 Workers Builds 日志，修复代码后重新推送；不要删除 Worker。
- GitHub Pages 失败：查看仓库 Actions 的 `Deploy portfolio to GitHub Pages`，修复后重跑。
- 后台无法登录：检查 GitHub OAuth callback URL、允许的 GitHub 用户名、Client ID/Secret、`SESSION_SECRET` 与浏览器 Cookie；不要绕过服务端签名校验。
- 后台可开但保存失败：检查 D1 绑定和迁移；作品外链可直接编辑，文件上传仅在所有者主动开通 R2 并配置 `MEDIA` 绑定后可用。
- 数据异常：先导出 `/api/site` JSON 和 D1 备份，再修复。
- 素材过大：保留原片外部备份，重新剪辑/压缩后上传，不要强行提高网页上传上限。
